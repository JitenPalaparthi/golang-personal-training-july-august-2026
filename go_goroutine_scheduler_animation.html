Important: Ps are not created because threads block.
GOMAXPROCS determines how many Ps can execute Go code simultaneously. If an M blocks in a syscall, its P can be detached and associated with another M. The runtime may create/wake an M so runnable Go work can continue. This animation keeps 4 Ps fixed while the M count changes.
Network I/O is different.
For pollable network descriptors, a goroutine is parked and the runtime's netpoller waits for readiness efficiently. When ready, the G is made runnable and can re-enter scheduling. This avoids dedicating one blocked OS thread to every socket.
